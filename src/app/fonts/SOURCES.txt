The brand fonts, served from the site's own files (next/font/local, src/app/layout.tsx).

Fetched 2026-11-20 the way next/font/google (Next 14.2.35) fetched them for every build
before then: the CSS from fonts.googleapis.com with next/font's user agent
(Chrome 104 on macOS), then the latin woff2 file for each weight from fonts.gstatic.com.
Each file is byte for byte the one vboadv.com was serving from /_next/static/media/
that day (production build of 01d76ed; its name there is on the "live" line).

Only the latin files. No page uses a character from Google's other subsets (latin-ext,
vietnamese; for Inter also cyrillic and greek); checked over every tracked text file,
2026-11-20. A word in one of those alphabets would show in the fallback face.

Every face carries Google's latin unicode-range, as the live faces did:
U+0000-00FF, U+0131, U+0152-0153, U+02BB-02BC, U+02C6, U+02DA, U+02DC, U+0304, U+0308,
U+0329, U+2000-206F, U+20AC, U+2122, U+2191, U+2193, U+2212, U+2215, U+FEFF, U+FFFD

Fallback faces (Arial, with the metrics the Google setup generated): fallbacks.css.
